## 1. `scripts/monthly_decision.py` → `src/pgr_vds/decision/`

The 4,080-line script (mypy-exempt) is now eleven modules behind a 72-line
`cli/monthly_decision.py` that only parses the command line. Function bodies
moved verbatim (a script sliced the original by AST node, so no body was
retyped); only the names and the cross-module calls changed.

**Names.** A function used from another module lost its leading underscore
(`_compute_aggregate_health` → `health.compute_aggregate_health`).
`_first_business_day_on_or_after` and `_reconstruct_ensemble_oos` had no
caller anywhere and were not carried over.

**One place to patch.** Every call into another `pgr_vds.decision` module goes
through the module (`health.compute_aggregate_health(...)`, never
`from .health import ...`). A test patches a function once, in the module
that defines it, and every caller sees the patch — the same behaviour the
tests relied on when everything lived in one namespace. The `signals`
DataFrame in `main` is why the module is `signal_generation`, not `signals`.

**`main`.** The blocks moved out of `main` are copied statement for
statement. Two orderings were kept on purpose: the ledger base folder is
still computed in `main` from `artifacts.output_dir` (a test that patches the
output folder also redirects the ledgers), and the operational DB snapshot
for the manifest is still taken before the retrain trigger writes its audit
row. The manifest warnings are now built after the retrain-trigger call
instead of around it; building them reads no state that call changes.

**What the run manifest says.** `run_manifest.json` now records
`script_name: "cli/monthly_decision.py"`, and its `cwd` for the git SHA is
the repository root computed from the module's location. The report footer
(`*Generated by \`scripts/monthly_decision.py\`*` in `recommendation.md` and
`diagnostic.md`) is left as it was, in one constant
(`rendering.REPORT_GENERATED_BY`), so the ten output files stay
byte-identical. Changing it is a one-line follow-up that changes every
report.

## 2. The `pgr_vds` package

`src/pgr_vds/` is the review's target package. It is installed as the
top-level package `pgr_vds` (`[tool.setuptools.packages.find]` now has
`where = [".", "src"]` and excludes `src.pgr_vds*`), so `pip install -e .`
makes `import pgr_vds` work from anywhere, next to `src` and `config`.
Because `src` is itself a package, the same files could also load as
`src.pgr_vds` — two copies of every module, two sets of globals, and
monkeypatches that silently miss one of them. `src/pgr_vds/__init__.py`
raises `ImportError` for that name.

The older packages (`src.models`, `src.database`, …) stay where they are;
moving them under `src/pgr_vds/` is a mechanical rename for a later step.

## 3. Type checking

The `[[tool.mypy.overrides]] module = "scripts.monthly_decision",
ignore_errors = true` block is gone. mypy on the new code found 14 errors,
all fixed without a runtime change:

| Where | Error | Fix |
|---|---|---|
| `portfolio.build_bl_diagnostics` | `build_bl_weights` returns `dict \| tuple`; the unpacking had a wrong-code `type: ignore[misc]` | `cast(tuple[dict[str, float], BLDiagnostics], ...)` (with `return_diagnostics=True` it always returns the tuple) |
| `diagnostic_report` (7), `recommendation_report` (1), `pipeline` (4) | `float(...)` / `str \| None` arguments from payload dicts typed `dict[str, object]` | the payload parameters (`shadow_gate_overlay`, `classifier_monitoring_summary`, `classification_shadow_summary`) are `dict[str, Any]`, which is what they hold |
| `diagnostic_report` (2) | `signals` may be `None` inside `if has_ci_data:` (mypy cannot narrow through the flag) | `if has_ci_data and signals is not None:` (`has_ci_data` already implies it) |

The EDGAR modules type-checked clean apart from `requests` having no
installed stubs (`# type: ignore[import-untyped]` on that import).

CI runs a new step, `python -m mypy --follow-imports=silent src/pgr_vds cli`
(21 files, `Success: no issues found`). `--follow-imports=silent` reports
errors in these files only; the older `src/` modules they import still have
errors of their own (for example `src/tax/capital_gains.py`,
`src/models/classification_shadow.py`), and hardening them is not part of
this step. The existing step for the 11 hardened modules is unchanged.

## Judgement calls

- **Top-level `pgr_vds`, not `src.pgr_vds`.** The review's layout is one
  installable package `pgr_vds`; installing `src/pgr_vds/` under that name
  now means the later move of `src.models` etc. is a rename into a package
  that already exists. The import guard keeps the second name out.
- **Eleven modules, not six.** The brief names six areas (data refresh,
  features and signals, health and gating, tax and lots, rendering,
  artifacts and ledgers). Rendering is three modules (the two report writers
  are 670 and 690 lines each), and `schedule`, `portfolio` and `pipeline`
  hold what fits none of the six (as-of date, redeploy/BL, the run itself).
- **`main` split further than moving.** The classifier shadow, overlays,
  console summary, BL diagnostic, ledgers, manifest warnings and manifest
  are named steps now (`main` 726 → 428 lines). Each is a copy of the
  original block; the golden replay covers them.
- **Report footer unchanged** (section 1): byte-identical output was the
  acceptance test.
- **`parse.py` stays 1,869 lines.** It is one parser whose
  `parse_html_exhibit` alone is 560 lines; splitting the parser was not in
  the brief and would need its own golden check on the EDGAR history.
- **The legacy fetcher's 59 tests were deleted, not ported.** They tested a
  different implementation (`parse_exhibit`, `fetch_monthly_8ks`,
  `backfill_to_db`) with no counterpart in the live code; the live parser's
  behaviour is covered by the seven `test_edgar_monthly_*` files.
